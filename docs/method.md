# 高密度个人识别型简历构建法

## 核心认知

简历不是经历列表，是个人能力结构的压缩证据链。HR 扫简历的时间很短，必须在几秒内判断：

- 这个人是什么样的人？
- 这个人会干什么？
- 这个人跟其他候选人有什么不同？

如果简历没有主动回答这三个问题，面试机会就会被稀释。

## 第一步：挖料

原则：不先问“你做过什么”，而是问“这件事里哪些是真的你干的，哪些是你参与的，哪些是你只是在场”。

操作：

- 把每段经历拆到最小可验证单元。
- 记录你使用的工具、采取的具体动作、产生的结果。
- 区分“主导”“独立完成”“参与协助”三个层级。
- 对自己的评价保持怀疑，把“我觉得”还原成事实。
- 对大一大二或项目少的用户，不只问实习、竞赛和获奖，也要从课程实验、社团微任务、帮助他人、AI 辅助学习、兼职临时任务和非典型技能里找真实证据。

证据格式：

```text
动作 + 工具/方法 + 结果
```

它可以兼容常见 STAR/CAR/PAR/XYZ 框架，但不被框架绑架。外部公式只用来追问缺失事实，不能替代真实性判断。具体适配见 [常见简历框架适配](common-resume-frameworks.md)。

对低素材用户，“结果”不一定是奖项或大数字，也可以是受益对象、交付物或企业价值：

```text
动作 + 工具/方法 + 受益对象/交付物/企业价值
```

示例：

```text
好：抢车号阶段使用 Codex 整理规则，上午第 31 名，主动调整策略后提升至第 19 名
弱：参与方程式赛车，负责电器相关工作
```

## 第二步：搭骨架

原则：HR 看完必须在心里给你归类。你需要主动告诉他你是谁，而不是让他猜。

可以用这个公式提炼个人识别标签：

```text
专业底盘 + 提效工具/方法 + 独特习惯/背景
```

示例：

```text
汽车工程底盘 + AI 工具应用 + 快速拆解和交付习惯
```

操作：

- 从所有经历中提取核心能力结构。
- 把最硬、最能经得起追问的经历放在简历前 1/3。
- 求职意向和正文第一屏必须互相呼应。
- 能独立讲清楚细节的经历放前面；只是参与、被追问容易卡住的经历往后放或合并。

## 第三步：写血肉

原则：每句话都要经得起追问。宁可写窄写准，不写宽写虚。

操作：

- 删除“锻炼了 XX 能力”“学习了 XX”“对 XX 有初步理解”等无证据表达。
- 用具体工具名称替代泛称，例如用“Codex”替代“AI 工具”，用“Altium Designer”替代“设计软件”。
- 量化结果写真实数字，不确定就写保守表达。
- 进行时和完成时区分清楚：没做完的事写“正在参与”，不要写成已经负责完成。

高频错误：

| 模糊表达 | 更稳的表达 |
| --- | --- |
| 负责 PCB 设计 | 基于参考模板修改 PCB，并完成指定模块布线 |
| 参与项目并提升能力 | 参与项目调试，定位并记录 3 类连接异常 |
| 熟练使用 AI 工具 | 使用 Codex 整理规则、生成检查清单并辅助比较策略差异 |

## 企业价值翻译

简历不是把经历堆满，而是回答：“这个人对企业有什么价值？”

即使用户没有硬核项目，也可以从小经历里翻译出企业能理解的价值：

| 用户素材 | 可翻译价值 |
| --- | --- |
| 经常帮助别人解决具体问题 | 服务意识、信任建立、团队融入 |
| 整理资料、会议记录、物资、签到、流程 | 降低沟通成本、基础运营可靠性 |
| 完成课程实验、报告、实训任务 | 执行力、专业基础、学习纪律 |
| 用 AI 工具学习、整理信息、辅助输出 | 快速适应、信息处理、工具杠杆 |
| 有特殊实操技能 | 稀缺记忆点、关系建立、手眼协调 |

不能只写“我有价值”，必须写出证明这个价值的真实动作。

## 非典型经历保留

不要机械删除和专业不直接相关但真实、有识别度的经历。先判断它是否能证明：

- 稀缺性或可记忆度。
- 主动帮助别人。
- 快速融入新集体。
- 建立信任关系。
- 服务意识。
- 组织协作。
- 跨领域学习。

例如中医针灸基础理论与实操学习经历，不应写成医疗能力或治疗效果，而可以保守表达为：

```text
中医针灸基础理论与实操学习经历；曾在校内团队活动中为同学、老师提供基础放松支持，帮助建立信任与融入协作环境。
```

这类经历通常放在附加资质、其他经历或个人特质，不应压过求职方向的核心证据。

## 活动不等于能力

不要只写“参加过 A 活动、B 活动”。活动数量本身不代表能力。每个活动都要追问：

- 用户在里面是什么角色？
- 具体做了什么动作？
- 使用了什么工具或方法？
- 帮到了谁？
- 产生了什么结果或交付物？
- 对目标岗位或企业有什么价值？

## 第四步：排兵布阵

原则：HR 不是读简历，而是扫简历。结构本身就是信息。

操作：

- 经历超过 4 条时，用分类标题承接扫读，例如“技术实践 / 商业实践 / 社区参与”。
- 每个分类下不超过 3-4 条，超过就合并同类项。
- 每条描述控制在 2-3 行，超过 4 行就拆点或精简。
- 倒序排列，最近的在前面；但黄金位优先放最能证明求职方向的硬证据。

合并信号：

- 同城市、同时间段、同主题的活动可以合并。
- 同一个项目下的设计、制造、调试、策略贡献可以分层展示。
- 只是“到场参与”的经历不单独占黄金位。

## 第五步：修门面

原则：简历写完后，删掉 20%。每一处删减都是对 HR 注意力的尊重。

操作：

- 遍历每条描述，问自己：面试时如果我答不上这个细节，它还应该留在简历上吗？
- 删除所有能被 AI 批量生成的套话。
- 删除和求职方向无关的冗余信息。
- 保留一句最有识别度的收口句。

## 面试压力测试

把简历交给朋友或自己随机抽查。对方随机指一个词，例如工具名、数字、芯片、项目名、策略名，你必须在 3 秒内开始讲清楚：

- 背景是什么？
- 我具体做了什么？
- 用了什么工具或方法？
- 遇到过什么问题？
- 最后结果是什么？

如果卡住，就执行以下处理：

| 卡住情况 | 处理方式 |
| --- | --- |
| 不能解释细节 | 删除或降级描述 |
| 只是参与，不是主导 | 改成“参与”“协助”“配合” |
| 数据记不准 | 核实后再写，或改成保守表达 |
| 工具只是听过 | 不写“熟练”，改写成真实使用场景 |

面试风险检查时，可以按严重程度分组：

| 风险等级 | 含义 | 处理方式 |
| --- | --- | --- |
| 高 | 很可能被追问，且当前证据不足 | 投递前降级、删除或补证明 |
| 中 | 能保留，但需要提前准备解释 | 保留前写好面试回答 |
| 低 | 只是细节澄清风险 | 保留，但准备背景信息 |

每条风险最好包含：

- 原始表述。
- 面试官可能怎么追问。
- 当前缺什么证据。
- “如果答不上来就删除/降级”的条件。

证据缺口可以按优先级标注：

| 优先级 | 含义 |
| --- | --- |
| 红色 | 必须补证明，否则删除或降级 |
| 黄色 | 建议面试前补好 |
| 绿色 | 可选背景信息 |

如果用户要求做面试风险检查，但没有提供简历正文或 bullet，先索要内容。不要默认编造示例，除非用户明确要求模拟；如果模拟，必须标注所有假设。

## 最终判断

如果只留一句话，HR 看完这份简历会记住什么？

这个答案应该来自简历里的证据，而不是来自自我评价。
