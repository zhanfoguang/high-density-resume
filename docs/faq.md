# FAQ

## 没有量化结果怎么办？

先找可验证结果，不要硬编百分比。可以写：

- 交付物：图纸、脚本、清单、报告、模板、活动、调研摘要。
- 规模：用户数、样本数、页面数、模块数、设备数。
- 周期：提前完成、缩短调试时间、减少返工次数。
- 对象：服务了谁、支持了哪个团队、影响了哪个流程。
- 前后变化：从混乱到清晰、从人工到半自动、从不可复用到可复用。

## 经历很普通怎么办？

普通经历也能拆出证据。不要问“这个经历厉不厉害”，先问：

- 我有没有真实做过一个具体动作？
- 我有没有用过一个具体工具或方法？
- 我有没有留下一个交付物？
- 如果面试官追问，我能不能讲清楚当时怎么做的？

只要答案里有事实，就能写得比套话更强。

## 项目只是参与，不是主导，怎么写？

诚实写参与边界。参与不是弱点，写不清楚才是弱点。

弱：

```text
负责项目整体推进。
```

稳：

```text
参与项目执行，负责整理用户反馈并按问题类型归类，输出需求表供后续迭代参考。
```

## 可以用 AI 帮忙写简历吗？

可以，但 AI 最适合做三件事：

- 追问你没说清楚的事实。
- 把经历拆成动作、工具/方法、结果。
- 帮你压缩语言，删除套话。

不要让 AI 替你编数据、编工具、编结果。简历是给面试追问用的，不是给模型表演文采用的。

## “熟练掌握”能不能写？

少写。除非你能用项目证据证明。

弱：

```text
熟练掌握 Altium Designer。
```

稳：

```text
使用 Altium Designer 修改参考 PCB 模板，完成指定模块布线并配合硬连线调试。
```

## 怎么判断一条经历该不该放黄金位？

优先放满足这些条件的经历：

- 和目标岗位强相关。
- 你能独立讲清楚细节。
- 有工具、方法、交付物或结果。
- 能体现你的个人识别标签。

如果经历很厉害但你讲不清楚，先不要放黄金位。

## 简历最后的综合评价要不要写？

可以写，但必须像“证据总结”，不要像“自我夸奖”。

弱：

```text
本人认真负责，学习能力强，沟通能力优秀。
```

稳：

```text
具备工程实践背景，能将项目经历拆解为规则、工具和交付物；在规则整理、现场支持和设计协作中习惯使用 AI 工具提高信息处理效率。
```
