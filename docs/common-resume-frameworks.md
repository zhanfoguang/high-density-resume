# 常见简历框架适配

这份文档用于把流传较广的简历方法论接入“高密度个人识别型简历构建法”。核心判断是：这些框架可以帮助追问事实，但不能压过真实性和面试可追问性。

## 总原则

```text
高密度证据链 = 真实归属 + 动作 + 工具/方法 + 结果 + 面试可解释
```

STAR、CAR、PAR、XYZ、ATS 关键词都只是辅助工具。它们的价值是提醒我们还缺哪些事实，而不是把普通经历硬包装成强经历。

## STAR / CAR / PAR

| 框架 | 适合场景 | 在本方法中的用法 |
| --- | --- | --- |
| STAR：Situation, Task, Action, Result | 面试故事、复杂项目复盘 | 用来追问背景、任务、动作、结果 |
| CAR：Challenge/Context, Action, Result | 项目 bullet、成就表达 | 用来补“为什么做”和“做完怎样” |
| PAR：Problem/Project, Action, Result | 把职责改成成果 | 用来把“参加/负责”拆成问题、动作、结果 |

简历 bullet 不一定要完整写出 STAR 的四段。更推荐压缩成：

```text
动作 + 对象/背景 + 工具/方法 + 结果
```

如果用户说不出结果，不要编数字。可以追问：

- 交付物是什么？
- 帮到了谁？
- 是否被采用、提交、通过、复用？
- 有没有前后变化？
- 有没有排名、范围、数量、时间、反馈？

## XYZ

常见的 XYZ 公式是：

```text
Accomplished X as measured by Y by doing Z
```

可以翻译成：

```text
通过 [动作/工具/方法] 完成 [交付物/结果]，[数字/范围/反馈/排名] 可验证。
```

对应关系：

| XYZ | 证据链 |
| --- | --- |
| X：完成了什么 | 结果或交付物 |
| Y：如何衡量 | 数字、排名、范围、反馈、采用情况 |
| Z：怎么做到 | 动作 + 工具/方法 |

注意：没有 Y 时，不要为了好看硬造指标。可以用“交付物、受益对象、采用情况、审核通过、问题解决、复用情况”等非数字证据替代。

## ATS 与关键词

ATS 友好不是“骗过系统”，而是让简历能被机器解析、让 HR 搜索到真实关键词。

应该做：

- 使用常见栏目名，例如教育背景、项目经历、专业技能、工作经历。
- 用简单排版，避免图片化简历。
- 目标岗位关键词自然出现在经历和技能中。
- 技能栏只写用户能解释的工具和能力。

不要做：

- 隐藏关键词。
- 硬塞不相关关键词。
- 把没有做过的岗位名写进简历。
- 相信任何“保证 ATS 通过”的说法。

## 融合优先级

当外部框架和事实冲突时，按这个顺序判断：

1. 真实性和归属边界。
2. 面试可追问性。
3. 求职方向和企业价值。
4. HR/ATS 搜索率。
5. 公式是否漂亮。

一句话：公式服务证据，证据不服务公式。
