# 用户入口分流工作流

真实用户不会都拿着完整简历来。使用这个 Skill 时，先判断用户给了什么，再选择不同工作流。

## 输入类型

| 用户输入 | 进入工作流 | 目标 |
| --- | --- | --- |
| 只有姓名、学校、专业、求职方向等零散信息 | 从零开始采矿 | 通过追问挖出经历和证据单元 |
| 用户说“没什么可写”、项目少、只有课程/社团/兴趣技能 | 低素材挖掘 | 从小经历中提炼真实动作、受益对象、企业价值和个人识别度 |
| 一段项目、比赛、活动经历 | 单段经历拆解 | 提炼动作、工具/方法、结果和追问点 |
| 一份已有简历 | 简历审查与重构 | 先诊断打分，再提出追问和修改计划 |
| 多个 AI 版本或审稿建议 | 双 AI 交叉审稿 | 用户筛选建议，保留真实和识别度 |

## A. 从零开始采矿

适合用户只提供很少信息的情况，例如：

```text
我大二，智能制造专业，想找实习，会一点 Python，参加过比赛。
```

不要直接生成完整简历。先问一轮必要问题。

### 第一轮追问

```text
1. 你的目标岗位或方向是什么？
2. 教育背景是什么？专业、年级、主修课程、排名或绩点有没有可写信息？
3. 最近 1-2 年做过哪些项目、比赛、社团、实习、活动或个人作品？
4. 每件事里你具体做了什么？哪些是你主导、独立完成、参与协助？
5. 用过哪些工具、软件、方法、平台？
6. 有没有交付物、数字、排名、用户、作品链接、上线结果或前后变化？
7. 哪些内容你面试时能讲清楚，哪些讲不清楚？
8. 目标岗位需要哪些关键词？这些关键词有没有真实经历支撑？
```

### 输出顺序

1. 证据单元表。
2. 已有信息 / 缺失事实 / 可写方向表。
3. 缺失信息和继续追问清单。
4. 求职方向与个人识别标签。
5. 简历骨架。
6. 事实足够后，再给第一版简历草稿。

### 低经历用户挖掘路径

大一、大二或项目经历少的用户，不一定没有素材。可以追问：

- 课程实验和实验报告。
- 课程设计或期末大作业。
- 自学笔记是否形成了清单、教程、代码、图纸或报告。
- 小制作、维修、仿真、排故、调试尝试。
- 社团或团队里的文档整理、设备检查、会议记录、资料归档等微任务。
- AI 辅助学习案例：输入了什么、如何验证、产出了什么。
- 帮老师、同学、团队、客户或家人解决过的具体问题。
- 非典型技能：是否能证明助人倾向、团队融入、信任建立、服务意识或稀缺记忆点。
- 兼职、家庭事务、临时任务中的执行、沟通、协调和交付。

这些经历不是天然弱，关键是能否讲出真实动作、工具/方法和产出。

### 低素材追问方式

不要只问“你有什么项目”。改问更小的问题：

```text
1. 最近一年哪个课程作业、实验或报告最费劲？
2. 你有没有帮老师、同学、社团或团队解决过具体问题？
3. 你有没有组织过人、资料、物资、签到、现场流程或文档？
4. 你用过哪些工具？哪怕只是 Excel、CAD、AI 工具、剪辑、设计、硬件工具。
5. 你有没有一个别人容易记住你的特殊技能？
6. 哪些事情你面试时能讲出真实细节？
```

每条素材都用下面路径翻译：

```text
小经历 -> 具体动作 -> 工具/方法 -> 谁受益 -> 结果/交付物 -> 对企业有什么价值
```

可翻译的企业价值包括：执行可靠、降低沟通成本、团队信任、服务意识、组织协调、快速适应、稀缺记忆点。

### 非典型经历处理

不要因为经历和专业不直接相关就机械删除。先判断它是否能证明：

- 个人识别度或稀缺性。
- 主动帮助他人。
- 快速融入新团队。
- 建立信任关系。
- 服务意识。
- 组织协调。
- 跨领域学习。

例如中医针灸基础学习经历，如果用户确实在校内团队活动中用它帮助同学、老师做基础放松支持，可以作为低优先级的团队融入和助人信号保留。但不能写治疗、治愈、诊断或医疗承诺。

## B. 单段经历拆解

适合用户只发一段项目或比赛经历的情况。

先拆：

```text
动作 + 工具/方法 + 结果
```

再判断：

- 参与层级是否清楚？
- 有没有工具名？
- 有没有交付物？
- 有没有真实数字？
- 能否经得起面试追问？
- 是否和目标岗位相关？

如果用户说“基于模板修改 PCB”，必须追问：

- 实际改了什么：原理图、布局、元器件参数、封装、接口定义、走线路径、文档？
- 用了什么软件？
- 是否打样、焊接、测试或上车使用？

如果用户说“排名变好”“效果提升”“成绩提升”，必须先要到前后数字、百分比、区间或排名背景，才能使用“提升”“优化”“改善”等表述。

输出：

- 证据单元。
- 追问问题。
- 保守版表达。
- 标准版表达。
- 高密度版表达。若数字、参与边界、工具或结果还没确认，只给带占位符的草稿，不要假装事实已知。
- 风险提示框。若用户无法提供可验证数字、具体改动或面试能讲清楚的细节，建议不写入简历，或只保留为保守的参与/学习表述。

## C. 已有简历审查与重构

适合用户已经给出完整或半完整简历的情况。

先做输入完整性检查。如果用户要求审查简历，但没有粘贴简历正文，不要打分、不要模拟、不要重写。先请用户补充简历，并说明可接受格式：

- 纯文本。
- Markdown。
- 带标题分区的文本。
- 从简历复制来的项目符号列表。

可以展示后续诊断模板，让用户知道你会怎么处理，但不能虚构诊断内容。

不要一上来重写。先做诊断：

1. 按评分表评价真实性、个人识别度、求职方向匹配、HR 搜索率、面试可追问性、结构扫读性。
2. 指出最强证据、最大风险和主线断裂点。
3. 增加关键词映射：目标关键词 -> 简历位置 -> 证据强度 -> 缺失证明。
4. 列出需要追问的 5-10 个问题。
5. 给出修改计划。
6. 用户补事实后，再重写。

输出结构：

```text
整体判断
评分表
关键词映射
关键风险
追问清单
修改计划
可先改写的局部
```

## D. 双 AI 交叉审稿

适合用户已经拿到多个模型建议，希望进行二次筛选的情况。

使用 [双 AI 交叉审稿流程](dual-ai-review-workflow.md)。

重点不是让 AI 决定，而是让用户把建议分成：

- 采纳
- 驳回
- 部分采纳
- 需要补事实

## 默认原则

- 材料少时，多追问，少生成。
- 用户觉得自己普通时，先从小动作里找企业价值，不要急着判定“没东西可写”。
- 材料多时，先诊断，后重写。
- 事实不清时，先降级，不夸大。
- 目标岗位不清时，先问求职方向。
- 用户要求“直接优化”时，也要先指出追问风险。
