# 面试主线与最小补证计划

## 面试主线

只为最终进入 `core` 的岗位优势生成主线。每条主线必须同时包含：

- 岗位要求 ID；
- 简历中的主张和证据 ID；
- 30 秒回答；
- 2 分钟展开结构；
- 可能追问；
- 可展示或复核的作品、数据、报告、代码或过程记录；
- 无法解释时的降级或删除条件。

30 秒回答使用：

```text
场景 + 本人动作 + 关键方法 + 结果/交付物 + 与岗位的关系
```

2 分钟回答依次说明背景、本人责任、方案选择、执行步骤、困难、验证方式、结果和反思。不得背诵简历原句，也不得补造过程细节。

面试问题优先追问强动词、数字、工具、所有权、失败处理和结果验证。`needs-detail` 或 `conflict` 证据只能生成核验问题，不能生成假定事实成立的回答。

## 缺口分类

- `材料缺口`：用户可能做过，但当前材料没有可引用证据；
- `所有权缺口`：做过相关工作，但无法证明独立或主导；
- `结果缺口`：有行动，没有可验证结果或交付物；
- `场景缺口`：底层能力相近，但没有目标行业、对象或流程经验；
- `能力/实践缺口`：用户确认尚未完成相关学习或实践。

只有用户确认后，才能把缺口归为能力/实践缺口。否则优先列核验问题。

## 最小补证任务

对已确认的能力/实践缺口，给出能产生真实证据的最小任务，而不是只列课程名称。每项任务写明：

1. 对应岗位要求；
2. 要完成的真实任务；
3. 最小交付物；
4. 验证方式；
5. 完成后可加入证据库的字段；
6. 预计前置知识或工具，但不承诺完成时间。

示例：

```text
缺口：没有独立输出数据分析报告的证据
任务：选择一份公开数据，完成清洗、三项分析和结论复核
交付物：代码、处理说明、图表、两页报告
验证：代码可重复运行，结论能回链到处理后的数据
入库条件：用户确实完成并能解释方法后，再新增证据 ID
```

补证计划不能被提前写成既有经历，也不能保证通过面试或获得录用。
