# 高密度经历证据链

## 目标

把用户已经做过的事写清楚，而不是把普通经历包装成更大的经历。每条可发布表述应尽量包含：

```text
动作 + 工具/方法 + 结果或交付物
```

缺少某一项时，追问或使用保守版本；不能为了形式完整而补造。

## 所有权层级

| 用户事实 | 可用表述 |
| --- | --- |
| 主导并能说明决策范围 | 主导、负责、设计 |
| 独立完成明确任务 | 独立完成、搭建、实现 |
| 与他人共同完成 | 参与、协作完成、贡献于 |
| 只做局部支持 | 协助、支持、配合 |

没有确认所有权时，默认使用“参与”或“协助”，并追问本人负责的范围。

## 事实挖掘顺序

1. 本人具体做了什么动作？
2. 使用什么工具、方法或判断过程？
3. 面向谁或解决什么问题？
4. 产生什么文件、作品、改动或可观察结果？
5. 所有权、范围和数字是否能经得起面试追问？

对经历较少的学生，继续检查课程作业、实验、社团微任务、帮助他人、兼职、自学产物、小型制作和 AI 辅助学习，但只保留与目标 JD 有可解释关联的真实行动。

当用户说“没什么可写”时，不重复追问“大项目或实习”。改问更小、更具体的事实：

- 最近一年最费力的课程作业、实验或报告是什么；
- 是否帮老师、同学、社团、团队或客户解决过一个真实问题；
- 是否整理过人员、数据、资料、设备、现场流程或文档；
- Excel、Python、CAD、AI 工具等分别用于过什么输入、操作和输出；
- 是否有能体现精确执行、服务意识、团队信任或跨领域学习的非典型经历。

每次只问最影响当前岗位判断的 3–5 个问题。先输出“已有事实 / 缺失事实 / 可能形成的证据方向”，关键事实足够后再生成正式简历。

## 岗位价值翻译

普通经历不能只靠活动名称进入简历。依次检查：

```text
原始经历 → 本人动作 → 受益对象 → 结果/交付物 → 对目标岗位或组织的价值
```

岗位价值可以来自专业能力、推进交付、减少沟通或整理成本、协作支持、服务意识、快速适应或真实稀缺性。价值结论必须由证据支持；不能把“参加次数”直接翻译成组织能力，也不能把帮助行为夸大成专业资质。

看似与 JD 不直接相关的真实经历，先检查是否证明团队信任、服务意识、组织执行、精确性或跨领域迁移。存在可解释价值时可标记为差异化素材；没有时保留在证据库，但不占用本岗位简历篇幅。

## 安全改写

- 将“熟练掌握 Excel”改为“使用 Excel 完成报名信息去重并输出签到表”，前提是事实存在。
- 将“负责 PCB 设计”降级为“基于参考模板修改 PCB，并使用 Altium Designer 完成已确认的局部调整”，前提是用户能说明修改范围。
- 没有数据时写清交付物，不编造提升百分比。
- 有排名或前后变化时要求确切数字和统计口径。
- 关键词只放进能支持它的证据表述，不单独堆砌。

## 面试压力测试

对每个工具、数字、项目名和强动词检查：

- 背景是什么？
- 本人做了什么？
- 为什么用该方法？
- 遇到什么困难？
- 结果如何验证？

无法回答时，降级措辞、移除数字或暂不写入正式简历。
