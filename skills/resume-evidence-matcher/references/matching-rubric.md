# 证据匹配判定规则

## 1. 要求拆解

- 一个要求只表达一种可判断能力、经验或资格。
- 合并重复和近义要求，避免重复计分。
- `must` 仅用于 JD 明示“必须/要求/至少”或履职不可缺少的核心条件。
- `preferred` 用于“优先/加分/熟悉”及辅助性条件。
- 无法从 JD 判断重要性时，保守标记为 `preferred` 并说明原因。

## 2. 证据强度

优先使用以下信息：

1. 明确交付物或可检查结果；
2. 具体动作和工具/方法；
3. 经用户确认的范围、角色和数字；
4. 仅有自我评价、关键词或课程名称的陈述。

课程、证书和“熟悉某工具”不能自动证明实际应用能力。它们可以作为补充信息，但需要项目动作或产出才能形成强证据。

## 3. 映射状态

### direct

证据的动作、场景和结果直接覆盖要求。例如，岗位要求“使用 SQL 完成业务分析”，证据明确包含 SQL 查询、分析对象和交付结果。

### transferable

证据证明相同底层能力，但行业、工具或对象不同。例如，用 Python 清洗实验数据可支持“数据处理能力”，但不能直接证明熟悉目标公司的数据仓库。

### partial

证据只覆盖要求的一部分，或缺少所有权、范围、方法、结果之一。例如只写“参与用户调研”，但没有说明本人执行了什么。

### gap

当前材料没有可引用证据。表述为“材料未提供证据”，不得直接断言“用户不会”。

## 4. 覆盖率解释

覆盖率只衡量已提供材料对 JD 要求的证据覆盖：

- 80–100：材料覆盖较完整，仍需核验关键事实；
- 60–79.9：存在可投递基础，优先补齐关键缺口；
- 40–59.9：匹配证据分散，需要补材料或调整目标；
- 0–39.9：当前材料不足以支撑该岗位，不等同于用户没有能力。

不得把区间解释成录用概率、人才等级或人格评价。

## 5. 示例

JD 要求：`R1（must）使用 Excel 进行运营数据整理和周报输出`。

用户事实：`E2 使用 Excel 整理 300 条社团报名记录，制作去重后的签到表并交付负责人`。

映射：`transferable`。证据直接证明 Excel 数据整理和交付，但没有周报或运营指标分析场景。

安全改写：`使用 Excel 整理 300 条报名记录并完成去重，输出可直接用于现场签到的名单（E2）`。

禁止改写：`熟练使用 Excel 搭建运营数据看板并持续优化周报效率`。
