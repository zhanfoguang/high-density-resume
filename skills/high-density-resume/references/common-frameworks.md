# Common Resume Frameworks

Use this reference when the user mentions STAR, CAR, PAR, XYZ, accomplishment bullets, impact statements, ATS optimization, or widely shared resume formulas.

## Adapter Rule

Do not replace the evidence-chain method with an external formula. Use external frameworks as lenses for missing facts:

```text
high-density evidence chain = ownership boundary + action + tool/method + result + interview defensibility
```

## STAR / CAR / PAR

These frameworks are useful when the user describes a story or project but the bullet lacks context or impact.

| Framework | Resume use | Evidence-chain mapping |
| --- | --- | --- |
| STAR: Situation, Task, Action, Result | Good for interview stories and complex projects | Situation/Task -> context; Action -> user's concrete action; Result -> outcome or deliverable |
| CAR: Challenge/Context, Action, Result | Good for accomplishment bullets | Challenge/Context -> problem/need; Action -> method; Result -> measured or observable change |
| PAR: Problem/Project, Action, Result | Good for turning duties into achievements | Problem/Project -> target object; Action -> concrete verb; Result -> benefit |

Do not force all STAR details into a resume bullet. For bullets, compress to:

```text
action + object/context + tool/method + result
```

If the result is missing, ask for the beneficiary, deliverable, before/after change, saved time, reduced error, ranking, adoption, feedback, or decision enabled.

## XYZ

The XYZ formula is:

```text
Accomplished X as measured by Y by doing Z
```

Use it when the user has a real, measured outcome. Map it as:

| XYZ part | Evidence-chain equivalent |
| --- | --- |
| X: accomplishment | result or completed deliverable |
| Y: measurement | number, rank, scope, volume, time, quality, adoption, or before/after |
| Z: method | action + tool/method |

Safe pattern:

```text
Achieved/Completed [X], measured by [Y], by using [Z].
```

Chinese pattern:

```text
通过 [动作/工具/方法] 完成 [交付物/结果]，[数字/范围/反馈/排名] 可验证。
```

If Y is missing, do not invent a metric. Use a non-numeric proof:

```text
deliverable, user/teacher/team feedback, visible adoption, repeated use, review passed, submission completed, issue resolved
```

## ATS / Keyword Advice

Treat ATS advice as parseability and truthful keyword alignment, not a promise that the system will pass the resume.

Use:

- Familiar section names.
- Single-column or simple structure.
- Text-based PDF/Word/Markdown, not image-only resumes.
- Target-role keywords naturally inside evidence-backed bullets.
- A skills section only for tools the user can explain.

Reject:

- Hidden keywords.
- Keyword stuffing.
- Fake job titles.
- Graphics-heavy templates that reduce parsing.
- Claims that any score guarantees interviews.

## When Frameworks Conflict

Use this priority order:

1. Truthfulness and ownership.
2. Interview defensibility.
3. Target-role relevance and enterprise value.
4. Keyword/searchability.
5. Formula elegance.

If a formula makes the line sound stronger than the facts, downgrade the line.

## Quick Prompts To Ask

For STAR/CAR/PAR:

```text
What problem or need existed?
What did you personally do?
What tool or method did you use?
What changed, who benefited, or what was delivered?
What would an interviewer ask you to prove?
```

For XYZ:

```text
What was accomplished?
How can it be measured or verified?
What did you do to create that result?
Which part was yours versus the team's?
```
