# HR And ATS Screening

Use this reference when the user asks for HR searchability, ATS/machine screening, resume layout, or target-role keyword alignment.

## Conservative Template Rule

Resume layout should reduce reading and parsing cost. Do not create visual novelty for its own sake.

Use familiar sections:

- Basic information.
- Target role or summary line.
- Education.
- Internship / practice / project experience.
- Campus or community experience.
- Skills.
- Certificates.

Avoid:

- Complex tables, text boxes, icons, progress bars, and decorative two-column layouts.
- Core information embedded inside images.
- Keyword-only blocks disconnected from real experience.

Before final delivery, remind the user to export a PDF whose text can be copied and searched.

## Feed Machines Truthful Keywords

Target-role keywords should appear naturally in evidence-backed bullets, not only in a skills list.

For intelligent manufacturing roles, possible keywords include:

- intelligent manufacturing
- automation
- electrical control
- PLC
- PCB
- Altium Designer / EasyEDA / Lichuang EDA
- UG / CAD
- sensor
- equipment debugging
- industrial electrical control
- Python
- AI Agent

Weak:

```text
Familiar with PLC, PCB, AI tools, and intelligent manufacturing.
```

Safer:

```text
Participated in vehicle electrical wiring and sensor debugging, modified a reference PCB with Altium Designer / EasyEDA, and used Codex to organize car-number selection rules for timed answering.
```

## Resume Is Built From Work

If the user lacks facts, do not keep polishing. Ask for or suggest evidence-generating work:

- Complete a course design and keep the report.
- Turn a lab into a reusable checklist.
- Build and publish a small tool.
- Take a concrete role in an activity and record the deliverable.
- Use AI tools to solve a real problem and record input, process, verification, and output.

## Enterprise Value Check

For each resume line, ask:

```text
What value does this prove for the target role or organization?
```

Value can come from:

- Professional ability: technical work, engineering, design, debugging, analysis.
- Execution: moving a task toward delivery.
- Learning: entering unfamiliar domains quickly.
- Collaboration: integrating into a team, helping others, supporting on-site work.
- Cost value: taking basic tasks and reducing team workload.
- Scarcity: a truthful, explainable combination of abilities that is uncommon.

Use:

```text
what I did -> role value -> evidence -> scarcity/recognition signal
```

## Activity Experience

Activity count is not evidence. Each activity must answer:

- What task did the user own or support?
- Who benefited?
- What problem was solved?
- What deliverable or result remains?
- Which ability is visible from the facts?

Weak:

```text
Participated in many campus activities and improved organizing ability.
```

Safer:

```text
Supported a campus practice activity by organizing registration data, assisting on-site flow, and distributing materials for 50+ participants.
```

## Five-Second HR Scan

Check whether a reader can see within 5 seconds:

- Target role.
- Target-role keywords.
- Strongest evidence.
- Enterprise value.
- One memorable difference.

If not, fix the target-role line, first-third evidence, and keyword distribution before polishing language.
