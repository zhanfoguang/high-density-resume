# Method Reference

## Core Idea

A resume is a compressed evidence chain for a person's capability structure. Each line should help answer: who is this person, what can they do, and what makes them different?

## Evidence Unit

Use:

```text
action + tool/method + result
```

Examples:

| Weak | Dense |
| --- | --- |
| Participated in Formula Student and handled electrical work | Modified PCB from a reference template, used Altium Designer for assigned module routing, and supported hard-wiring debugging |
| Used AI tools to improve efficiency | Used Codex to organize car-number selection rules, compare strategies, and improve ranking from 31st in the morning to 19th |

## Ownership Levels

Use honest scope:

| Level | Meaning |
| --- | --- |
| Led | Owned direction, decisions, and final delivery |
| Independently completed | Completed a defined scope alone |
| Participated/assisted | Contributed to part of a larger effort |

Do not change `participated` into `led` just because the bullet sounds stronger.

## Positioning Formula

```text
professional base + leverage/tooling + distinctive working habit/background
```

Example:

```text
Automotive engineering base + AI-assisted rule decomposition + fast structured delivery habit
```

## Resume Arrangement

- Put the strongest, most defensible experience in the first third.
- Align target role, positioning line, and first core experience.
- Use sections when there are more than four experiences.
- Keep each experience to 2-3 lines unless the role requires deeper technical detail.
- Merge related activities from the same period, location, or theme.

## Pressure Test

Randomly point to any tool, number, project, or strong verb. The user must be able to explain:

- Context
- Their action
- Tool or method
- Problem encountered
- Result or deliverable

If they cannot explain it, downgrade or delete the wording.
